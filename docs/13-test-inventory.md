# 13 — The reference's own test suite, file by file

Generated by `tools/test_inventory.py` from the pinned reference
(`references/Cataclysm-DDA/tests`). Do not edit by hand: rerun the script.

This page counts the **reference's** cases, not the port's. The port's own test count comes from
`cargo test --workspace` (the `passed` figures it prints, summed); quoting these numbers as the port's
is a mistake this port made for several rounds and corrected at round 293.

The per-file triage (re-express as a test, keep as an invariant, reproduce as
a session, or drop with a reason) lives in [parts/test-triage.md](parts/test-triage.md);
this page is the mechanical inventory it is checked against.

This is the map of what upstream already asserts, so that a ported system
can be checked against the same expectations rather than reinvented. It is
**not** an equivalence oracle — see [14-test-porting.md](14-test-porting.md)
for why, and for the rules that turn a case here into a test in the port.

## Shape of the suite

* **206 of 218 files contain test cases** - the rest are helpers - giving **1217 cases**, 83,037 lines of test code.
* **758 cases need a running game** (`g->`, an avatar, a map, a spawned NPC or monster); the other **459** exercise algorithms and data on their own.
* **69 cases carry `[slow]`** and CI runs them in a batch of their own; **{hidden} carry `[.]`**, which means CI skips them entirely.
* Upstream seeds from the clock (`--rng-seed time`) and generates random
  inputs in 27 files, so a failure is not always reproducible. A ported
  case fixes its seed — that is a strict improvement, not a deviation.

## How to read the table

| Column | Meaning |
|---|---|
| Cases | `TEST_CASE` count in the file |
| Lines | size of the file |
| Needs a world | the file reaches for game state, so the case cannot run before that subsystem exists |
| Tags | upstream's own labels, the ones CI filters on |
| Port status | what the port has taken from it so far |

## The wires: what each stage reaches (audit at round 1039)

Two rounds found the same shape - **a rule that is right and nothing calls** - so this is the ledger of what the schedule actually reaches, stage by stage. A rule is
**reached** only if a stage on `environment_schedule` gets to it, directly or through one of these calls.

| Stage | Set | What it reaches |
|---|---|---|
`scheduled_stage` | Scheduled | the scheduled effects that have come due, for the avatar |
`scent_stage` | Scent | the scent trail's own advance |
`falling_stage` | Falling | falling, and the support check under it |
`fields_stage` | Fields | the field sweep, with the wind, the map facts and the refusing-gas set |
`creatures_stage` | Creatures | **`focus_stage`** (morale, pain, sleepiness, the equilibrium, the drift), then dressing, reaping the dead, and every creature's turn |
**`needs_stage`** | Creatures | the sleepiness clock **both ways** - climbing while awake, recovering while `Asleep` |
`light_stage` | Light | clearing the light and casting it again |

**Three things this ledger makes visible, and none of them are visible from a test count:**

1. ~~**The food clock is not on it.**~~ **Closed at round 1040**: `digest_stage` runs every five minutes in the creatures set, reads the creature's own cache for
   `STOMACH_SIZE_MULTIPLIER`, and hands the body its half hours. **Still open:** its vitamin and effect tables are empty until a loader installs them.
2. **`focus_stage` runs inside the creatures stage, not as its own.** The order is still declared (it is first in `creatures_stage`, before anything acts), but a reader
   looking down `add_systems` will not find it - the ledger is where that is written down.
3. ~~**Nothing reads a creature's enchantment cache into the body.**~~ **Closed at round 1040** for mutations; **still open** for items and effects, which are the cache's other
   two sources.

**A rule is not ported because it has a test; it is ported because a turn can reach it.** The three items above are the current backlog, in that order: the food clock's
stage, its enchantment inputs, and then the two rules that wait on them.
