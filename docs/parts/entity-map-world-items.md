## 5. Ambiguities (what extra reading would settle each)

1. **`map` — entity or index?** It is a fixed 11×11×Z *window* over `mapbuffer`, yet `game` treats it as "the world" (`reality_bubble()`, map.h:2265). *Settle by:* reading `map::shift` (map.cpp:7949) and `map::loadn` (map.cpp:8144) to confirm `grid` is never authoritative, and by checking whether any save path serializes `map` directly.
2. **`mapbuffer` — cache or entity?** It holds the only in-RAM copy of submaps, but evicts them to disk and reloads from `save_quad` (mapbuffer.h:87). *Settle by:* reading `mapbuffer::save`/`unserialize_submaps` (mapbuffer.cpp) to see whether a submap's contents survive unload intact or are regenerated.
3. **`scent_map` — component or entity?** `grscent` is authoritative per-tile simulation state, but it is not addressable by any id and is discarded on map shift (`scent_map::shift`, scent_map.cpp:82). *Settle by:* reading `scent_map::update`/`decay` (scent_map.cpp:50–70) to see how much survives a shift.
4. **`itype::item_variables` — prototype or shared mutable state?** It is a per-type `global_variables::impl_t` on a shared prototype (itype.h:1389) that gets copied into `item::item_vars` (item.h:3280). If any code path writes through the prototype, "immutable shared definition" is false. *Settle by:* grepping every write site of `item_variables` in item.cpp / item_factory.cpp / global_vars.cpp.
5. **`pocket_data` — pure prototype?** It carries `_no_unload`/`_no_reload`, marked `NOLINT(cata-serialize)` and described as mirroring the *parent item's* flags (item_pocket.h:556–558). That is instance state on a prototype. *Settle by:* finding every writer of `_no_unload`/`_no_reload`.
6. **`inventory` — component or scaffolding?** It owns real items (authoritative for carried goods) yet is also a query/UI surface (`invlet_cache`, `binned_items`). *Settle by:* checking whether `Character` has a second item store, which would demote `inventory` to a view.
7. **`field_entry::decay_time` — authoritative or derived?** Ctor sets it 0 (field.h:23), `initialize_decay` fills it later (field.h:80). Whether it is redundant with `age` + field type is unproven. *Settle by:* reading `field_entry::initialize_decay` and `do_decay` in field.cpp.
8. **`submap::reverted`** is `NOLINT(cata-serialize)` (submap.h:312) — if it is not persisted, is it a cache or a transient mapgen flag? *Settle by:* reading `submap::revert_submap` / `get_revert_submap` (submap.h:94–96).
9. **`zone_options` — prototype or per-entity component?** Declared as a type family (clzones.h:74–345) but instantiated per zone (clzones.h:366). *Settle by:* reading whether `zone_options::create` returns fresh instances per zone or shared singletons.
10. **`zone_manager::types`** is `NOLINT(cata-serialize)` (clzones.h:562) yet looks like the prototype registry for zone types. *Settle by:* reading `zone_manager`'s constructor to see where `types` is populated.
11. **`map::submaps_with_active_items_dirty`** (map.h:2140) — a second set that mirrors the first; whether it is a work queue or a cache is unestablished. *Settle by:* reading `map::update_submaps_with_active_items` (map.cpp).
12. **`lightmap.h` has no class at all** — so "the lightmap" as a concept is entirely `level_cache::lm`. Confirmed by reading lightmap.h:1–86 in full; flagged only because the scope names `lightmap.*` as if it owned state.
