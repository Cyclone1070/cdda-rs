# Reference corpus

Frozen evidence produced by the reference implementation, used as the
specification for the port. Nothing here is written by hand: every file is
generated by a program under [`oracle/probes/`](../oracle/probes/), and the
generator is committed next to its output.

| File | Generator | What it pins down |
|---|---|---|
| `rng/engine.csv` | [`rng_corpus.cpp`](../oracle/probes/rng_corpus.cpp) | The reference's random stream: `minstd_rand0` raw draws, plus `uniform_int`, `uniform_real` and `normal` distributions over four seeds |
| `prototypes/digest.json` | `cataclysm --dump-prototype-digest` (see [11-oracle-harness.md](../docs/11-oracle-harness.md)) | Every loaded prototype registry: 90 registries, 54,925 prototypes, each as a count plus an FNV-1a digest of its sorted ids |
| `prototypes/ids.json` | `cataclysm --dump-prototype-ids` | The same registries with every id spelled out, so a difference can be read rather than hunted |
| `env/env-seed12345.json` | `cataclysm --seed 12345 --dump-env` | The state before any world: RNG position, calendar, and the five options the simulation reads. Only reproducible with an explicit seed |
| `options/table.json` | [`gen_options.py`](../tools/gen_options.py) | Every option the reference declares: name, type, default, range, page (276) |
| `state/state-seed12345.json` | `cataclysm --seed 12345 --dump-state` | A game started headlessly: RNG position, calendar, avatar, and a tile-level digest of the reality bubble. Byte-identical across runs |
| `text/msgids.txt` | [`gen_msgids.py`](../tools/gen_msgids.py) | Every message id the C++ marks for translation (11,058 keys), so the port can prove its lookup returns them unchanged |

## Rules

- **Never hand-edit a corpus file.** Regenerate it with its probe, and commit both
  together, so the diff shows what changed about the reference rather than what
  someone typed.
- **Attribute surprises to the generator, not the port.** If the port disagrees
  with the corpus, the corpus wins until a re-read of the reference proves the
  generator was measuring the wrong thing.
- **A corpus is evidence about one build.** `rng/engine.csv` records what this
  standard library does on this platform; a different standard library may draw
  differently, which is exactly why the file exists rather than a reimplementation
  of the specification from memory.

## Why the RNG corpus comes from a probe and not the game

Standard-library distributions are implementation-defined, so the numbers depend on
the standard library the game is built with — not on the game's own code. The probe
therefore uses the same generator and the same distributions, with no game code
involved, which makes it reproducible on any machine with the same toolchain and
removes any chance of the game's configuration leaking into the numbers.

The prototype dumps are byte-identical across runs (three runs, same hash), which
is what makes them usable as a gate: if the port's digest differs, the port is
different.

## Regenerating

```
cd oracle/probes
clang++ -std=c++17 -O1 rng_corpus.cpp -o rng_corpus
./rng_corpus > ../../corpus/rng/engine.csv
cd ../.. && cargo test -p cdda-core-types
```

For the prototype dumps, from the repository root:

```
oracle/build.sh
./oracle/build/src/cataclysm --datadir oracle/src/data/ --userdir oracle/userdir \
    --dump-prototype-digest corpus/prototypes/digest.json
./oracle/build/src/cataclysm --datadir oracle/src/data/ --userdir oracle/userdir \
    --dump-prototype-ids corpus/prototypes/ids.json
```

The trailing slash on `--datadir` matters: several paths are built by string
concatenation, and without it the game looks for `datatitle/` instead of
`data/title/`.
